# PromptingGo

PromptingGo — веб-приложение для публикации, поиска и использования промптов. Автор может подготовить готовый текст или шаблон с полями, отправить публикацию на модерацию и выпускать новые версии. Посетитель может найти промпт, заполнить его параметры и скопировать результат.

Сайт: [https://promptinggo.ru](https://promptinggo.ru).

В репозитории сохранены имена solution, проектов и пространств имён `PromptHub`. Производственная БД, пользовательские файлы и настройки развёрнутого сайта в репозиторий не входят.

## Возможности

- Каталог с категориями, тегами, фильтрами, сортировкой и поиском.
- Готовые промпты и конструктор шаблонов с переменными и условными блоками.
- Черновики, версии, очередь модерации, публикация, отклонение и архивирование.
- Модерация изображений, изменений подписей, жалоб на промпты и комментарии.
- Избранное, оценки, комментарии, профили авторов и уведомления внутри приложения.
- Загрузка изображений и аватаров, миниатюры, обложки и упорядочивание медиа.
- Поиск похожих публикаций для модератора.
- Настройка ссылок поддержки автора через CloudTips и ЮMoney; приложение не обрабатывает платёжные реквизиты банковских карт.
- Sitemap, robots.txt и правила индексирования публичных страниц.

## Стек и организация кода

.NET 10, ASP.NET Core MVC, Razor Views и Razor Pages для Identity, EF Core 10, Npgsql/PostgreSQL, ASP.NET Core Identity, SkiaSharp, libphonenumber-csharp. Интерфейс использует CSS и JavaScript; библиотеки Bootstrap, jQuery и jQuery Validation включены в статические ресурсы проекта.

Приложение организовано как один веб-проект с контроллерами, моделями представления и сервисами предметных областей. Зависимости регистрируются в `Program.cs`; доступ к данным проходит через `ApplicationDbContext`.

| Путь | Назначение |
| --- | --- |
| `PromptHub.Web/Controllers` | MVC endpoints каталога, публикаций, профилей, модерации, медиа, уведомлений и администрирования |
| `PromptHub.Web/Areas/Identity` | Регистрация, вход, подтверждение email, восстановление доступа и управление аккаунтом |
| `PromptHub.Web/Models` | Сущности, перечисления состояний и модели представления |
| `PromptHub.Web/Data` | DbContext, конфигурации EF Core, миграции и импорт стартового каталога |
| `PromptHub.Web/Services` | Поиск, рендеринг шаблонов, медиа, модерация, метрики, уведомления и внешние интеграции |
| `PromptHub.Web/Views`, `ViewComponents`, `wwwroot` | Razor-интерфейс, компоненты и статические ресурсы |
| `PromptHub.Tests` | Модульные и интеграционные тесты |
| `Dockerfile`, `compose.yaml` | Пример сборки веб-контейнера и локального запуска с PostgreSQL |

## Identity и роли

Вход по email и паролю реализован через ASP.NET Core Identity. Перед входом требуется подтверждение email. Есть восстановление пароля, блокировка после неудачных попыток входа, обновление security stamp и ограничения частоты запросов.

Явные роли — `Administrator` и `Moderator`. Обычный зарегистрированный автор не требует отдельной роли `User`. Проверки владельца публикации и прав сотрудников находятся в контроллерах и сервисах доступа.

Телефонная аутентификация и OTP-инфраструктура сохранены, но по умолчанию выключены через `Features:PhoneAuthentication:Enabled`. Для Development предусмотрен только локальный отправитель OTP. Включение телефона в Production требует отдельного провайдера доставки и проверки связанных сценариев.

## Публикации и модерация

У публикации есть состояния `Draft`, `PendingModeration`, `Published`, `Rejected`, `Archived`. У версии — `Draft`, `PendingModeration`, `Published`, `Rejected`. Текущая публичная версия отделена от рабочей: редактирование опубликованного промпта не должно само по себе заменять видимый посетителям текст.

Модератор рассматривает конкретную версию, может одобрить или отклонить её и работать с жалобами. Для медиа предусмотрены собственные состояния и отдельная модерация изменений метаданных. Уведомления сохраняются в БД. Ограничения уникальности и concurrency tokens защищают часть инвариантов версий, обложек и обновления медиа.

## Данные и поиск

PostgreSQL хранит Identity-аккаунты, публикации и версии, переменные шаблонов, категории, теги, комментарии, оценки, избранное, жалобы, уведомления и метаданные файлов. Полная история EF Core migrations сохранена.

Поиск сочетает `ILIKE`, русскоязычный full-text search и триграммное сходство `pg_trgm`, а также ранжирование совпадений в заголовке, описании, тегах и тексте текущей опубликованной версии. Модераторский поиск дубликатов использует триграммное сходство и GiST-индексы. Внешнего поискового сервиса или интеграции с LLM для выполнения промптов в исходниках нет.

В Compose используется образ PostgreSQL `pgvector/pgvector:pg18-trixie`. Поисковая реализация проекта использует `pg_trgm`; наличие pgvector в образе не означает реализацию поиска по embeddings.

## Медиа

Оригиналы изображений и аватары хранятся вне `wwwroot`, в `App_Data`. В БД находятся относительные ключи и метаданные. Контроллеры применяют правила доступа перед выдачей файлов.

Проверяются расширение, MIME type, сигнатура, размер файла, размеры изображения и число декодированных пикселей. SkiaSharp создаёт WebP-миниатюры и обрабатывает аватары. Сервисы поддерживают обложку, порядок изображений, конкурентные изменения, отложенное удаление и очистку несвязанных файлов.

Команды обслуживания поддерживают предварительный просмотр без удаления:

```bash
dotnet run --project PromptHub.Web --launch-profile http -- --cleanup-prompt-media --dry-run
dotnet run --project PromptHub.Web --launch-profile http -- --cleanup-orphan-prompt-media --dry-run
```

## Локальный запуск

Нужны .NET 10 SDK, Docker Engine/Desktop и Docker Compose v2. Команды ниже выполняются из корня репозитория; пример задания переменной окружения использует Bash.

1. Подготовить локальные настройки и запустить БД:

   ```bash
   cp .env.example .env
   # Установите собственный POSTGRES_PASSWORD в .env.
   docker compose up -d postgres
   ```

2. Восстановить пакеты и локальный инструмент EF:

   ```bash
   dotnet restore PromptHub.slnx
   dotnet tool restore
   ```

3. Задать строку подключения для запуска приложения на хосте:

   ```bash
   dotnet user-secrets set "ConnectionStrings:DefaultConnection" \
     "Host=localhost;Port=5433;Database=prompthub;Username=prompthub;Password=change-me" \
     --project PromptHub.Web
   ```

   Замените пароль, порт, имя БД и пользователя значениями из своей `.env`. `change-me` — только пример. Если пароль содержит разделители строки подключения, корректно экранируйте его по правилам Npgsql.

   `.env` автоматически читает Docker Compose. Обычный `dotnet run` этот файл не загружает: используйте user-secrets или переменную `ConnectionStrings__DefaultConnection`.

4. Применить миграции и запустить веб-приложение:

   ```bash
   ASPNETCORE_ENVIRONMENT=Development dotnet ef database update --project PromptHub.Web
   dotnet run --project PromptHub.Web --launch-profile http
   ```

   В PowerShell окружение задаётся отдельно: `$env:ASPNETCORE_ENVIRONMENT = "Development"`.

Открыть [http://localhost:5100](http://localhost:5100). Миграции автоматически при запуске не применяются.

В Development ссылки подтверждения email и восстановления пароля выводятся в локальный лог; внешняя доставка не выполняется. Для проверки используйте тестовый аккаунт. Эти логи содержат действующие одноразовые ссылки, поэтому они исключены из репозитория.

### Локальный администратор и каталог

Development-seeder создаёт роли. Автоматическое назначение администратора по умолчанию отключено: `DevelopmentAdmin:Email` пуст.

Чтобы проверить административные сценарии, сначала зарегистрируйте и подтвердите локальный аккаунт, затем установите его email через user-secrets и перезапустите приложение:

```bash
dotnet user-secrets set "DevelopmentAdmin:Email" "admin@example.com" --project PromptHub.Web
```

`admin@example.com` здесь обозначает ваш тестовый аккаунт. Для контейнерного запуска соответствующая переменная в `.env` — `DEVELOPMENT_ADMIN_EMAIL`. Этот механизм работает только в Development и не создаёт пользователя или пароль автоматически.

Через административный интерфейс можно создать категории и теги, затем добавить собственный тестовый промпт. Стартовый JSON-каталог содержит 330 шаблонов; его импорт опционален. Он требует существующего автора и всех активных категорий/тегов со slug из JSON. Импортёр сообщает об отсутствующих справочниках и не заменяет настройку новой БД:

```bash
dotnet run --project PromptHub.Web --launch-profile http -- \
  --import-initial-catalog --author-email=admin@example.com
```

## Тесты

```bash
dotnet build PromptHub.slnx -c Release
dotnet test PromptHub.slnx -c Release
```

Тесты охватывают рендеринг шаблонов, переменные конструктора, правила медиа и модерации, обработку изображений, Identity/OTP, ссылки поддержки автора и SEO. Для HTTP-проверок используются `WebApplicationFactory` и тестовые реализации зависимостей. Часть сценариев использует EF Core InMemory; PostgreSQL-сценарии запускают изолированные контейнеры через Testcontainers и требуют работающий Docker.

Для запуска только части, не требующей Docker:

```bash
dotnet test PromptHub.slnx -c Release \
  --filter 'FullyQualifiedName!~PhoneOtpServiceTests&FullyQualifiedName!~AuthPagesTests&FullyQualifiedName!~PromptDuplicateDetectionServiceTests'
```

Этот фильтр исключает проверки OTP с БД, части Identity и триграммного поиска; он не заменяет полный прогон.

## Docker и конфигурация окружений

`compose.yaml` предназначен для локального знакомства с проектом. PostgreSQL и веб-порт привязаны к loopback. Веб-сервис включается профилем `web`; он работает в Development. После настройки `.env` и применения миграций из предыдущего раздела:

```bash
docker compose --profile web config --quiet
docker compose --profile web up -d --build
docker compose logs -f web
```

Открыть [http://localhost:8080](http://localhost:8080). Пароль, имя пользователя и БД для контейнера Compose передаёт из `.env`. Именованные volumes разделяют БД, runtime-медиа и ключи ASP.NET Core Data Protection. Удаление volumes удалит соответствующие локальные данные.

В Dockerfile используется многоэтапная сборка, а в runtime приложение запускается от непривилегированного пользователя `app`. `Dockerfile` и `compose.yaml` позволяют собрать приложение и запустить локальное окружение с PostgreSQL. Production-развёртывание настраивается отдельно.

Для отдельной настройки Production используются следующие параметры. Для email, SmartCaptcha и контактного email оператора включена проверка настроек при запуске:

| Параметр ASP.NET Core | Назначение |
| --- | --- |
| `ConnectionStrings__DefaultConnection` | Доступ к собственной PostgreSQL |
| `AllowedHosts` | Разрешённые домены своего экземпляра |
| `UnisenderGo__ApiKey`, `UnisenderGo__FromEmail` | API-ключ и подтверждённый отправитель писем |
| `SmartCaptcha__Enabled`, `SmartCaptcha__ClientKey`, `SmartCaptcha__ServerKey` | Включённая капча и ключи для своего домена |
| `Legal__ContactEmail` | Контакт оператора; имя и адрес задаются отдельными полями `Legal` |

Имена `UNISENDER_GO_API_KEY` и `SMARTCAPTCHA_*` из `.env.example` преобразуются в настройки приложения в `compose.yaml`. Для запуска без Compose используйте имена ASP.NET Core из таблицы.

TLS, доверенный reverse proxy, резервное копирование, доступ к данным и хранение ключей необходимо настроить для своего окружения отдельно. В репозитории нет готового production-deploy или CI/CD-конвейера.
